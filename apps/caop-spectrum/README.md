# CAOP matrix spectrum

Compute single-particle or general-operator Green functions using a block
continued-fraction representation generated by the block Lanczos method in a
fixed selected excitation basis. The calculation uses MPI/OpenMP and supports
both `double` and `complex<double>` at runtime. It reuses SBD's Hamiltonian
construction, stored/on-the-fly multiplication, MGS and distributed inner products.
Optionally, Hamiltonian application can call the existing Thrust GPU on-the-fly
`mult`. This is partial GPU support: stored multiplication, applied-operator seed
generation and the remaining Lanczos operations run on the CPU.

## Build and test

From this directory:

```sh
make CCCOM=mpicxx CCFLAGS='-std=c++17 -O3 -fopenmp'
make check CCCOM=mpicxx CCFLAGS='-std=c++17 -O3 -fopenmp'
```

Override `SBD_PATH` (default `../..`), `SYSLIB`, `MPIEXEC`,
`MPIEXEC_NUMPROC_FLAG`, and `PYTHON` as needed. On macOS with Homebrew libomp
and OpenBLAS, use:

```sh
make CCFLAGS='-std=c++17 -O3 -Xpreprocessor -fopenmp -I/opt/homebrew/opt/libomp/include' \
  SYSLIB='-L/opt/homebrew/opt/libomp/lib -lomp -L/opt/homebrew/opt/openblas/lib -llapack -lblas'
```

The root CMake build includes `caop-spectrum`. Enable
`-DSBD_BUILD_SPECTRUM_TESTS=ON` for the generic remap/block-Lanczos and CAOP/CLI
tests, then run `ctest --test-dir <build> -R spectrum --output-on-failure`.
Tests use Python 3.10+ standard-library oracles, MPI 1/2/4 and OpenMP up to 3 threads.
Python is not a dependency of the executable. `SBD_COMPLEX` does not change its
runtime type selection. Keep OpenMP teams fixed; the CLI requests
`MPI_THREAD_FUNNELED` and disables dynamic teams.

### Existing GPU on-the-fly `mult` integration

With the existing NVHPC CMake toolchain, select `-DSBD_GPU_BACKEND=thrust`
and the appropriate `-DSBD_GPU_ARCH`. Build the `caop-spectrum` target and pass
`--hamiltonian-mode on-the-fly` to use the existing CAOP GPU `mult`.
`caop-spectrum` uses the same `sbd_configure_diag` helper as `caop_diag` in
Thrust builds. Configure both in one build tree to share compiler, optimization,
CUDA architecture, MPI staging and BLAS/LAPACK options:

```sh
cmake --build <build> --target caop_diag caop-spectrum --parallel 4
```

For Make builds, both CLIs accept the same `CCCOM`, `CCFLAGS` and `SYSLIB`
overrides. With NVHPC, the shared flags include `-std=c++17 -O3 -mp -cuda
-gpu=cc100,mem:separate,nointerceptdeallocations -DSBD_THRUST
-DSBD_NON_CUDA_AWARE_MPI`; pass the same NVPL LP64 sequential libraries via
`SYSLIB`. Set the architecture to match the target GPU.

CAOP defaults to `SBD_CAOP_THRUST_MEMORY_MODE=separate`, applying
`mem:separate,nointerceptdeallocations` to both `caop-spectrum` and `caop_diag`.
GDB/TPB retain their existing settings. For comparisons, select
`-DSBD_CAOP_THRUST_MEMORY_MODE=unified` to restore
`mem:unified,interceptdeallocations`. Existing CMake build trees retain their
cached choice; pass `-DSBD_CAOP_THRUST_MEMORY_MODE=separate` explicitly when
updating a build tree previously configured with unified memory.

The default `stored` mode still applies H on the CPU, including in Thrust builds.
Other backends currently leave this application on the CPU.

A single `CaopMultThrust` driver owns GPU resources for one spectrum call and is
reused across all block columns and Lanczos steps. Input/output vectors remain
on the host; the driver performs transfers and MPI reductions. Seed generation,
QR, Lanczos vector arithmetic and continued-fraction evaluation remain on CPUs.
Each block column is applied sequentially. Use the same rank-to-GPU assignment
as CAOP diagonalization (for example, one visible GPU per MPI rank). When MPI
cannot access CUDA buffers, set `-DSBD_NON_CUDA_AWARE_MPI=ON`.
The settings log reports the actual Hamiltonian application backend.

The existing `spectrum_cli` test runs real/complex, stored/on-the-fly and MPI
cases against analytic/Python oracles. In a Thrust build its on-the-fly cases
exercise GPU application; local-basis helper tests remain CPU tests. Run GPU
CLI tests in an allocation with a valid GPU assignment for every MPI rank.

## Generate and reevaluate

```sh
OMP_NUM_THREADS=2 mpirun -np 2 ./caop-spectrum \
  --hamfile ham.txt --sites 16 --bit-length 64 \
  --loadname state- --wavefunction-shards 4 \
  --orbitals 0,2,4 --channel addition --reference-energy -7.5 \
  --extra-detfile excited-basis.txt --steps 100 \
  --save-coefficients addition.coeff --output addition.csv \
  --omega-min -10 --omega-max 10 --points 401 --eta .1

./caop-spectrum --read-coefficients addition.coeff --output narrower.csv \
  --omega-min -10 --omega-max 10 --points 801 --eta .05
```

Paths and physical parameters are illustrative. Generation requires
`--save-coefficients`; CSV output is optional. Reevaluation requires `--output`
and does not read the Hamiltonian or wavefunction. Output files are replaced.
The CLI rejects exact input/output path collisions; choose distinct output paths.
Saved coefficients support frequency/broadening changes, not restarting the
Lanczos iteration itself.

`--orbitals` uses zero-based CAOP mode indices. Select `--channel removal` for
the removal channel and provide the corresponding excitation basis. For general
operators, replace `--orbitals`/`--channel` with:

```text
--applied-operator-type general --operator-file op0.txt --operator-file op1.txt
```

Each file is an existing CAOP operator file, in observable order, with the same
fermion/hard-core-boson statistics as H. Operators may be non-Hermitian or change
particle number. Use `--scalar-type complex` for complex H, states or operators.
`--wavefunction-type real` explicitly promotes real saved amplitudes into a
complex calculation; otherwise the checkpoint type defaults to the scalar type.

`--hamiltonian-mode stored` is the default; `on-the-fly` stores only diagonal
terms and computes other contributions during H application. Both operate on
the same fixed selected basis. `--h-comm-size H` and `--t-comm-size T` default
to one; H*T must divide the MPI size, and b = MPI size/(H*T). Basis ownership is
distributed over b, H terms over h, and multiplication tasks over t. Gram/norm
reductions count only the unique b rows. Checkpoint input is read on h=t=0.
During seed generation each b shard of parent determinants and amplitudes is
further partitioned over h and t; every rank applies all observable operators
to its own parents. Operator terms and seed columns are not partitioned.
Contributions are routed to their b hash owner, then summed by determinant and
column over t and h. The completed excitation basis and all seed columns are
replicated over h/t before QR and Hamiltonian operations. These later operations
use the original h/b/t communicators and ownership. General operators are
replicated on all ranks for seed generation; the full parent state is not.

## Runtime logging

The CLI prints resolved settings as `#` records and runtime messages with
`make_timestamp()` and the `sbd::spectrum:` prefix, on world rank zero.
Workflow boundaries are flushed even when stdout is redirected to a file.
They cover checkpoint/extra-basis/operator/Hamiltonian reading, optional remap,
seed generation and QR, Hamiltonian preparation, Lanczos, coefficient I/O,
and response evaluation with CSV writing.

`--iteration-log-interval N` controls completed-step messages: 0 (default)
disables them, 1 prints every step, and N prints multiples of N. Workflow
messages and the final result/total time remain enabled. Iteration records
report the current and next block rank and elapsed Lanczos time.

Seed preparation reports the reference determinant count, the unique union
of generated determinants before extra-basis inclusion, and the final excitation
basis count. Generated rows include zero or cancelled amplitudes; this is not a
nonzero-support count. Counts exclude h/t replicas. QR reports the number of
input vectors and the retained rank.

Stage times are world-rank-zero wall times, not sums of rank times. The total
is the maximum local elapsed time across ranks, from after argument parsing
through computation, coefficient saving and optional CSV output, before MPI
finalization. Nested stage times should not be added to the total. These logs
are workflow timings, not hardware profiles or rank-by-rank load-balance reports.

Library calls remain silent by default. Optional final callback arguments to
`spectrum` and `block_lanczos` deliver workflow and iteration information on
all participating ranks without prescribing a stream or output format.

## Wavefunction and basis contract

`ReadWavefunctionCheckpoint<ElemT>` reads the native files produced by CAOP
`SaveWavefunction`: `PREFIX000000.bin`, ..., `PREFIX(N-1).bin`. It recovers both
determinants and amplitudes. Original determinant text files are unnecessary.
Saved shard count is independent of the current MPI decomposition. Each b rank
reads its row interval from every shard and the reader redistributes records to
unique hash owners, preserving amplitudes without normalization. This differs
from existing `sbd::LoadWavefunction`, which matches amplitudes to a supplied
basis and normalizes the result. See the reader's Doxygen contract in
`sbd/caop/spectrum/checkpoint_io.h`.

The binary format uses native size_t/ElemT and has no endian, scalar type,
Hamiltonian, energy or bit-length metadata. Specify the original type, sites and
bit length correctly. Missing/truncated files, inconsistent record sizes,
invalid bits/amplitudes and duplicate source determinants are rejected.
Rank-local exceptions are fatal to a CLI MPI run.

`--remap-detfile FILE` is optional and normally omitted: the checkpoint already
contains the reference determinant basis and amplitudes, so the original
basis text files are not needed. Specify this option only to remap the reference
state onto a different determinant set before applying the response operators.
Repeated files define the union of the target set. Determinants outside that set
are discarded, and new determinants receive zero amplitude. File order does not
specify MPI ownership or local ordering; the target is redistributed by hash.
Retained/discarded squared norms are reported;
normalization requires `--normalize-remap`. A non-unit reference is otherwise
rejected. After truncation, supply the appropriate reference energy explicitly;
the application does not recompute E0 or diagonalize a ground state.

The excitation basis is the union of determinants generated by the applied
operators and optional `--extra-detfile FILE` inputs. Extra rows initially have
zero seed amplitude and participate in PHP. Both text options accept unsorted,
overlapping records: one binary string of exactly `sites` characters per line,
mode 0 at the right. Seed support alone is usually insufficient. Neither H mode
automatically expands the determinant basis or completes a particle sector.
Mixed sectors are an explicit union, not inferred or enforced by the CLI.

## Response conventions and numerical limits

For addition and removal respectively:

```text
G+_ab = <psi0| c_a (omega+E0-H+i eta)^-1 c_b† |psi0>
G-_ab = <psi0| c_b† (omega-E0+H+i eta)^-1 c_a |psi0>
```

Removal transposes the seed-resolvent indices without conjugating them. Add the
two channels on a common orbital list/grid for the fermionic retarded response.
General operators produce `<psi0| O_a† (omega+E0-H+i eta)^-1 O_b |psi0>`.
Hard-core-boson channels are positive resolvents; a commutator response requires
its own combination of signs/frequencies. The spectral matrix is
`-(G-G†)/(2*pi*i)`, whose diagonal is `-Im(G_aa)/pi`.
CSV columns are `omega,orbital_a,orbital_b,G_real,G_imag,A_real,A_imag`, or
`operator_a,operator_b` for general operators.

Two-pass MGS factors the seed block F = Q1 C0 and deflates zero/dependent
columns. Block rank may decrease, with rectangular B blocks. The solver keeps
two large vector sets and O(steps*p*p) small coefficients. Seed generation,
remapping, sparse H and communication can require substantial additional memory;
this is not a whole-application memory bound. No global determinant replication
is introduced.

Only local reorthogonalization is performed; full Krylov history is not retained.
Long chains may lose orthogonality. `rank_threshold` is a numerical stop reason,
not proof of an exact invariant subspace. Check step count, basis and eta
convergence for each application. H must be Hermitian; projection checks do not
validate the complete Hamiltonian. Defaults: rank_atol=1e-13, rank_rtol=1e-12.

## Library components used

The CLI delegates its numerical work to these SBD components:

- `sbd::caop::spectrum::ReadWavefunctionCheckpoint` reads the reference state,
  and `sbd::RemapWavefunctionToBasis` matches amplitudes between basis layouts.
- `sbd::caop::spectrum::spectrum` constructs the operator-applied seed space and
  connects the existing CAOP Hamiltonian operations to the Lanczos recurrence.
- `sbd::sparse_solver::block_lanczos` generates the block coefficient chain,
  using SBD's distributed inner products and MGS through the block-vector helpers.
- The coefficient-based Green-function routines evaluate the response on the
  requested frequency grid, both after generation and during replay.

## Saved coefficient format

Small coefficient matrices are stored as row-major arrays. For m A blocks,
ranks has m+1 entries; A[j] is r_j*r_j, B[j] is r_(j+1)*r_j, and terminal_B
has dimensions r_m*r_(m-1) for a nonempty chain. C0 has dimensions
r_0*observable_count. These dimensions are validated before reevaluation.

The coefficient format is plain text, with no version number. Its header is
`EXTSBD_CAOP_SPECTRUM real` or `EXTSBD_CAOP_SPECTRUM complex`. Both scalar types
use the same layout for single-particle and general-operator responses.
This format is distinct from native binary wavefunction checkpoints. Prototype
files headed by version numbers 1/2/3 are no longer accepted; regenerate them
with this writer.

Records appear in this order:

1. Header (magic and scalar type).
2. `addition reference_energy basis_size`.
3. `fermion sites bit_length`.
4. `max_steps rank_atol rank_rtol orthogonality_tolerance`.
5. Observable count, then a line of orbital indices or operator-column indices.
6. Operator-file label count (zero or the observable count), followed by that
   many quoted paths. These are metadata; replay does not reopen these files.
7. `seed_discarded_norm max_local_correction stop_reason`.
8. C0 matrix, then the Lanczos step count m.
9. All m A matrices, all m-1 B matrices (none for an empty chain), and terminal_B.
10. The m discarded residual norms.

Each matrix is written as a `rows cols` line followed by its row-major values.
Real values are plain numbers; complex values use `(real,imag)` notation.
Numbers use 17 significant digits. Zero-size matrices have an empty value line.
Frequency points and broadening are specified at replay time, not stored here.

See [spin dimer](examples/spin_dimer/README.md) for an analytic four-state
example with real checkpoint promotion, complex Sy operators, and eta replay.
